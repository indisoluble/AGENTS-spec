# 02.1 — Acceptance

Acceptance defines how to evaluate the accepted requirements, applicable constraints and expressly accepted defining examples in [Formulation](../02.0-formulation/deliverables/baseline.md). It owns requirements-derived scenarios, fixtures, assertions, qualitative criteria, executable definitions and their [coverage record](deliverables/coverage.md).

Establish the written expectation before selecting the mechanisms it assesses. Implement executable checks as soon as feasible and run them during iteration. A prior written criterion can support a qualified engineering assessment even when no executable test drives implementation. Behavioral trials, artifact inspection and qualified assessment can establish different properties. Record which conditions each method exercises, what observations support a conclusion and what remains uncertain.

Base expectations on accepted intent. A mechanism change that preserves that intent should normally leave its acceptance criteria applicable. Cover every accepted requirement as far as reasonably and technically feasible, independently of checks elsewhere. Refer an ambiguous rule to its knowledge owner.
