# 03.1 — Conformance

Conformance defines complementary evaluations of mechanisms specified in [Design](../03.0-design/README.md), subject to the [applicable requirements](../02.0-formulation/deliverables/baseline.md). It owns its fixtures, scenarios, assertions, qualitative criteria, executable definitions and [coverage record](deliverables/coverage.md).

Write the expectation before implementing the mechanism in the Candidate. Implement and exercise executable checks as early as feasible. Record whether a criterion supports an executable test or a subsequent qualified assessment. Mechanism changes can require revised checks. Return ambiguous requirements or design prescriptions to their respective owners.

Conformance alone decides whether a mechanism check is redundant with [Acceptance coverage](../02.1-acceptance/deliverables/coverage.md). Compare purpose, semantics, preconditions, observations, assertions, scope and what each method can establish. A shared scenario or a particular execution result cannot settle that question. Record each omission against the Acceptance criterion and its version. Reconsider it when that coverage changes.
